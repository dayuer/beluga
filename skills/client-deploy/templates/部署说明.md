# {{NAME}} 部署说明(版本 {{VERSION}})

这个文件夹是你的应用的完整"安装包"。照下面做,就能让应用在你自己的服务器上上线。
**我们不会、也不需要登录你的服务器,更不需要你的任何密码。** 整个过程都在你的服务器上完成。

## 包里有什么

| 文件 | 作用 |
|---|---|
| `site/` | 应用本体(已经做好的网页文件) |
| `Dockerfile`、`docker-compose.yml` | 方式一:用 Docker 一条命令启动 |
| `docker-compose.https.yml`、`Caddyfile` | 方式一的升级版:自动配置 HTTPS(小锁头) |
| `nginx/default.conf` | Docker 里 Nginx 的配置(一般不用改) |
| `nginx/host-nginx.conf.example` | 方式二:服务器上已有 Nginx 时的配置示例 |
| `.env.example` | 可调整的设置(见下表) |

## 需要什么设置

只有两项,都放在 `.env` 文件里,**都可以不填**:

| 名字 | 用途 | 默认 |
|---|---|---|
| `HOST_PORT` | 普通版对外开放的端口 | 8080 |
| `DOMAIN` | HTTPS 版使用的域名(如 `app.example.com`) | 无(只有 HTTPS 版需要) |

这里没有任何密码或密钥。`.env` 是你自己的文件,不要发给别人。

## 你需要准备

- 一台能联网的 Linux 服务器(2 GB 内存就够)
- 服务器上装好 **Docker**(方式一),或 **Nginx**(方式二)
- (想要 `https://` 网址)一个域名,并且已经解析到这台服务器的 IP

## 方式一:Docker(推荐,最省事)

1. 把整个文件夹(或 `.tar.gz` 压缩包)传到服务器,进入文件夹:
   ```
   cd {{NAME}}-{{VERSION}}
   ```
2. 启动:
   ```
   docker compose up -d --build
   ```
3. 在浏览器打开 `http://服务器IP:8080`,看到应用首页就成功了。
4. 想换端口:`cp .env.example .env`,改 `HOST_PORT`,再执行第 2 步。

### 要 HTTPS(推荐正式使用)

1. 先到域名服务商那里,把域名解析到服务器 IP,并确认服务器放行 80 和 443 端口。
2. `cp .env.example .env`,把 `DOMAIN=` 后面填上你的域名。
3. 启动:
   ```
   docker compose -f docker-compose.https.yml up -d --build
   ```
4. 稍等一分钟,打开 `https://你的域名`。证书会自动申请、自动续期。

## 方式二:服务器上已有 Nginx

按 `nginx/host-nginx.conf.example` 文件开头的 4 步做即可(复制 `site/` 里的文件、复制配置、重载 Nginx、用 certbot 开 HTTPS)。

## 常用操作

| 想做的事 | 命令(在这个文件夹里执行) |
|---|---|
| 看是否在运行 | `docker compose ps` |
| 停止 | `docker compose down` |
| 看日志 | `docker compose logs --tail 50` |
| 更新到新版本 | 换上新的交付包文件夹,再执行 `docker compose up -d --build` |

## 打不开怎么办

- **浏览器一直转圈**:服务器防火墙/云厂商安全组没放行端口(8080,或 80 和 443)。
- **显示"无法连接"**:执行 `docker compose ps`,没看到 `Up` 就执行 `docker compose logs`,把输出发给我们。
- **HTTPS 申请失败**:十有八九是域名还没解析到这台服务器,检查解析后再重启。
- **手机上还是旧页面**:关掉应用重新打开一次;仍不行就清除浏览器缓存。

遇到解决不了的,把"哪一步、看到了什么"告诉我们(不用发密码)。
