# Synon Studio 四屏版式、状态与文案（M5）

> 配套：`docs/studio-mobile-ux.md`（交互规则与 `UX-*` 可检查项，本文不重复行为规则，只给版式、状态与文案）。原型：`docs/studio-mobile-ux.html`（390 宽可点；本文的桌面版式用线框图给出）。
>
> 范围：登录 `/login`、项目 `/`、项目首页 `/project/:id`、新需求 `/new?project=:id`。计划页、对话、决策、验收是 M6，不在本文展开，只引用共享组件与状态机。

## 0. 共同的视觉语言

### 0.1 Token（全部来自 `packages/companion/lib/theme.ts`，不新增）

| 用途 | Token | 浅色值 |
|---|---|---|
| 页面底 | `color.bg` | `#F6F6F7` |
| 卡片、输入框 | `color.card` | `#FFFFFF` |
| 标题栏 | `color.bar` | `#FFFFFF`（实色，底部 1px `hairline`） |
| 主文字 | `color.text` | `#1D1D1F` |
| 次文字 | `color.text2` | `#5D5D63` |
| 说明文字 | `color.text3` | `#737379` |
| 分隔线 | `color.hairline` / `hairlineStrong` | `rgba(0,0,0,.09)` / `.16` |
| 主按钮 | `color.primary` / `color.onPrimary` | `#1D1D1F` / `#FFFFFF` |
| 在等你、排队、离线 | `color.warn` + `tint.warn` | `#94600F` / `rgba(176,116,20,.10)` |
| 出错 | `color.error` + `tint.error` | `#B3352E` / `rgba(196,55,48,.085)` |
| 完成、在线、AI 在做 | `color.ok` | `#2E8550` |
| 链接、焦点 | `color.info` | `#2F64D0` |

- 间距只用 `space`：2/4/8/12/16/24/32/48；圆角只用 `radius`：8/12/14/20/pill；字号只用 `type`。
- 标题栏永远实色，没有渐变、毛玻璃、阴影；卡片是白底 + 1px 边框 + `shadowCss`（浅色下很轻）。
- 颜色只用于含义：琥珀=等你/排队/离线，红=问题，绿=完成/在线，蓝=链接/焦点。图标单色 `color.text2`。

### 0.2 版式骨架

**手机（390×844，基准）**

```
safe-top 47
┌──────────────────────────────────┐
│ Header 44（返回 / 标题 / 刷新）    │
├──────────────────────────────────┤
│ 可选横幅 34（离线 / 重连）         │
├──────────────────────────────────┤
│ 内容区 16 边距，可滚动             │
│ （底部留出 composer + dock）       │
│                                  │
│ 可选 Composer（输入框 + 选项 + 回执）│
├──────────────────────────────────┤
│ ActionDock：主按钮 52，左右 16      │
│ padding-bottom 16 + safe-bottom 34 │
└──────────────────────────────────┘
```

**桌面（≥900，1440×900 为基准）**

```
┌ 全宽实色标题栏 56 ──────────────────────────────┐
│  ‹ 返回   标题                                  刷新 │
├──────────────────────────────────────────────────┤
│           内容列最大 720，水平居中                │
│           项目卡片两列（352 + 16 + 352）          │
│                                                  │
├──────────────────────────────────────────────────┤
│           底部动作条：内容列宽 720 内主按钮 52     │
└──────────────────────────────────────────────────┘
```

- 断点 **900**：`<900` 用手机版式（390 的规则原样放大到 375–899），`≥900` 用桌面版式。
- 桌面标题栏 56 高，标题**左对齐**、紧跟返回；手机标题栏 44 高，标题居中。这是桌面和手机的真实差别，不是把手机版放大。
- 桌面内容列 720 居中；登录页例外，内容列 400。底部动作条的内宽跟着该屏的内容列（项目/首页/新需求 720，登录 400）。
- 桌面不依赖悬停或右键：卡片整块可点，焦点环 2px `color.info`；悬停只做很轻的背景变亮，不做功能。
- 手机安全区：`env(safe-area-inset-*)`；键盘弹起时 `bottom = inset`，dock 的 `padding-bottom` 降到 16（见 `studio-mobile-ux.md` §5）。

## 1. 登录 `/login`

**任务**：一个邮箱、一个按钮，30 秒内发完链接。没有注册、没有密码、没有第三方登录（P2 才有 Apple/Google）。

```
│                                  │
│  登录                             │ 24/700

│                                  │
│                                  │
│                     （弹性留白）   │
│                                  │
│  邮箱                             │ 13.5/500 text2
│  ┌────────────────────────────┐  │ 52
│  │ you@example.com            │  │
│  └────────────────────────────┘  │
│                                  │
├──────────────────────────────────┤
│  ┌────────────────────────────┐  │
│  │           继续              │  │ 52
│  └────────────────────────────┘  │
│           safe-bottom 34         │
└──────────────────────────────────┘
```

- 品牌方块 56×56、圆角 16、`color.primary` 底、白色鲸鱼标记；下面是 `type.title` 的「登录」和一句说明。
- 邮箱输入框贴着 ActionDock 上方（拇指区），不用滚屏就能点；输入区上方是弹性留白。
- **主按钮**：「继续」，ActionDock 内，52 高。全屏只有这一个实底按钮。
- 发送后同一位置把邮箱框下面的说明换成统一回执；按钮文案变「再发一封」，仍可点。
- 页面加载时若 URL 带 `#token=`：先 `history.replaceState` 去掉 fragment，再验证；验证中显示按钮内 spinner（不整屏遮罩）。

### 1.3 状态

| 状态 | 版式变化 | 文案（zh / en） |
|---|---|---|
| 默认 | 邮箱空，主按钮可点（提交时才校验） | — |
| 发送中 | 主按钮内 spinner、禁用 | 发送中… / Sending… |
| 已发送 | 邮箱框下出现回执面板（`sunken` 底、圆角 12）；按钮变「再发一封」 | 如果这个邮箱被邀请过，链接已发出。 / If this email was invited, the link is on its way. |
| 链接失效 | 回执面板换成 `tint.error` 底、`error` 字；不自动重发 | 链接已失效，请重新发一封。 / This link has expired. Request a new one. |
| 你已离线 | 顶部 `SyncBanner`；点「继续」后回执显示失败 | 你已离线 · 上次同步 x 分钟前 / You're offline · last synced x min ago |
| 发送失败 | 回执面板 `error`；按钮回「继续」可重试 | 没发出去：你现在没有网络。 / Not sent: you're offline. |
| 后端 5xx | 同上，文案换服务不可用 | 服务暂时不可用，稍后再试。 / The service is temporarily unavailable. Try again soon. |

- **空态**：邮箱空不是错误；主按钮保持可点，点了才校验并聚焦输入框。
- **出错**：只显示客户语言，不显示状态码、不显示「邮箱不存在」之类的差异（中台恒 202）。
- **离线**：横幅出现，但输入与按钮仍可用；提交失败按上面的「发送失败」处理。

## 2. 项目 `/`

**任务**：让客户扫一眼就知道「哪个项目有事等我」。卡片是入口，不是数据面板。

### 2.1 390 版式

```
┌ 47 safe ─────────────────────────┐
│              项目             ↻  │ 44；↻ 44×44
├──────────────────────────────────┤
│ 进行中                            │ eyebrow 12/600
│ ┌──────────────────────────────┐ │
│ │ 饮水打卡            青禾工作室 │ │ 名称 16/600；工作室 12.5 text3
│ │ AI 正在拆登录页的里程碑        │ │ callout text2，1 行省略
│ │ ● 在等你：确认平台            │ │ 8pt 琥珀点 + 12.5 caption
│ │ 工作室离线 · 上次同步 12 分钟前 │ │ 仅离线时第二行
│ └──────────────────────────────┘ │
│ ┌──────────────────────────────┐ │
│ │ 门店预约            山谷工作室 │ │
│ │ 还没有需求                    │ │
│ │ 工作室离线 · 上次同步 2 小时前 │ │
│ └──────────────────────────────┘ │
│                                  │
│ （无 ActionDock：本屏没有主按钮）  │
└──────────────────────────────────┘
```

- 卡片内边距 16、卡片间距 12；名称和工作室名同一行（名称 `flex:1` 省略），第二行一句话，第三行状态。
- 平台图标：**M5 不画**。中台 `Project` 只有 `name`，没有 platforms；组件接口预留 `platforms?: string[]`，空数组时不渲染这一行（见 §5 与 §7 的决定 1）。
- 圆点只在有客户要处理的事时出现（`plans` 中最新计划 `waitingOn === 'customer'`），文案是「在等你：<该计划的一句话>」；没有就省略。
- 工作室离线行和圆点行可以同时存在（上下两行），两者语义不同。
- 整张卡片是 `Pressable`（role=button），点任意位置进项目首页；没有箭头图标，避免「只有箭头能点」的误解。
- **主按钮**：本屏没有。刷新是标题栏右侧 44×44 图标按钮；空态的「刷新」是 `TextButton`，两者都不算主按钮。

### 2.2 桌面版式

```
┌ 实色标题栏 56：‹ 项目                                    ↻ ┐
├────────────────────────────────────────────────────────────┤
│                      内容列 720 居中                        │
│  进行中                                                     │
│  ┌───────────────────────┐  ┌───────────────────────┐      │
│  │ 饮水打卡     青禾工作室 │  │ 门店预约     山谷工作室 │      │
│  │ AI 正在拆登录页的里程碑 │  │ 还没有需求             │      │
│  │ ● 在等你：确认平台      │  │ 工作室离线 · 2 小时前   │      │
│  └───────────────────────┘  └───────────────────────┘      │

└────────────────────────────────────────────────────────────┘
```

- 卡片两列，最多两列；超过 4 个项目时按行排，不缩成三列（720 放三列会让中文标题太挤）。
- 卡片高度随内容，同一行等高（`align-items: stretch`）；空项目卡不要为了等高硬撑装饰。
- 标题左对齐；刷新按钮在最右。

## 3. 项目首页 `/project/:id`

**任务**：计划列表 + 一个明确的「新需求」。客户看懂「AI 做到哪、在等谁」，然后能加需求。

## 7. 决定与偏离

1. **M5 项目卡片不画平台图标**。中台 `GET /v1/app/projects` 只返回 `{id, studioId, studioName, name}`（`docs/studio-hub.md` §6.2），`Project` 也没有 platforms。BLG-84 的「平台图标」这一条按此记为 deferred：组件接口留 `platforms?`，M5 传空、不渲染；P2 协议加字段后再补。审计不应因此判不通过（M5 技术设计 §0 第 3 条）。
2. **桌面不是手机放大**：标题栏 56 且标题左对齐；项目卡片两列；新需求两列；登录内容列 400；动作条内宽跟内容列（720 / 400），不拉满 1440。
3. **M5 无底部导航**：只有「项目」一个根；M6 有「待办」后加两个 tab，主按钮仍在 ActionDock（见 `studio-mobile-ux.md` §1.1）。
4. **登录页主按钮在动作条**：与其它屏一致，拇指区可达；桌面动作条内宽 400。
5. **项目首页内容区不重复项目名**：标题栏已经是项目名；内容区只留工作室名和同步状态，减少层级噪音。
6. **「对话 · 3」只在 M6 出现**：M5 不画一个点不动的假入口。
7. **错误不暴露实现**：不显示 HTTP 状态、JSON、`daemon`/`hub`/`opId` 等词；所有文案走 `lib/strings.ts`，zh 默认 + en。
