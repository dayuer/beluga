# 联邦制：自动接单

几个人一起做一个项目时，每个人的 Beluga 跑在自己的电脑上，用自己的订阅和登录。**自动接单**打开以后，队友在共用看板上把一个任务派给你，你的电脑会自己开工：开一个 worktree，让你的 Claude 按任务的说明去做，不用你先点 Start。

这一页写的是现在已经做好的行为：里程碑 1 的定向派活，和里程碑 2 的认领池（见下面「认领池」一节）。`docs/tasks-and-plans.md` 里「Give it to a teammate's agent…」那一段是旧说法，以这一页为准。

## 前提

- 每台电脑各自装好 Beluga，各自登录 Claude。
- 互相加了好友，并且在同一个 GitHub 仓库上组成了团队，这样看板才是共用的（任务派给谁、状态，都在团队里同步）。
- 每台电脑上项目要用的 `.env` 等密钥由主人自己放好。自动接单不会传任何密钥。

## 怎么打开

Mac：**设置 › Agent › 自动接单**（在 Auto Route 下面）。

| 设置 | 管什么 | 默认 |
|---|---|---|
| 队友派给我的任务自动开工 | 关：什么都不自动开工。派给我的：队友派给你的就绪任务自己开工。派给我的，以及认领池：再加上从认领池里领任务 | 关 |
| 池标签 | 只在选了认领池时出现。带这个标签、还没人接的就绪任务算在池里。会去掉首尾空格并转成小写；清空就回到默认 | `pool` |
| 只接 | 完全信任的人：只有你设成「完全信任」的人派的才开工。信任的人：「信任」和「完全信任」都行 | 完全信任的人 |
| 同时进行 | 自动开工的任务最多同时跑几个，1–6，填别的数会被夹到这个范围里。多出来的留在 Ready 排队，有一个进评审或完成，下一个接着开 | 2 |

这些设置在 `~/.beluga/settings.json` 的 `federation` 里。它们是**这台电脑自己的**：不会随设置同步到你的其他电脑，因为每台电脑能跑多少、信任谁，各不相同。

手机（Beluga Link）不提供这个设置。

**关着时什么都不变**：不监听看板变化，不读看板，不开任何 worktree。和没有这个功能时一模一样。

## 什么时候开工

下面每一条都满足，任务才会自己开工。一个任务没动，就从上往下对一遍，第一条不满足的就是原因：

1. **派给了你**：任务的负责人是你。
2. **状态是 Ready**：Backlog、进行中、评审中、已完成的都不动。
3. **在范围内**：不是私人任务，不在归档里，不属于某个计划（计划的任务由计划自己推进）。
4. **是团队任务**：在和队友共用的看板上，看得出是谁派的。
5. **不是你派给自己的**：你自己把任务派给自己，不会自动开工，还是你自己点 Start。
6. **没被挡住**：它依赖的任务都已进评审或完成。依赖的任务在这台电脑上找不到，也算挡住。
7. **还没有 worktree**：已经开过的不会再开第二个。
8. **没有别人在做**：没有队友正在他们的电脑上做它。
9. **信任够**：派活的人在你这里的信任级别达到「只接」的要求。
10. **有名额**：自动开工、还在进行中的任务数少于「同时进行」。你自己手动开的 worktree 不占名额。

（方案里写的是 8 条；这里把「在范围内」和「不是自己派的」分开写，所以是 10 条。）

## 它什么时候看一眼

队友改了任务派给谁或状态、这台电脑上的任务状态或 worktree 变了、队友的电脑上线、你刚把设置打开、Beluga 启动时。一阵连续的变化只算一次（约 200 毫秒内合并）。

每次都从看板重新算：哪些是自动开工的，从任务的活动记录里认（「你的 Claude，替派活人」把它移到了进行中）。所以 Beluga 重启后不会把同一个任务再开一遍，也照样知道已经占了几个名额。

开工失败（比如刚好有人先开了），只在黑匣子日志里记一行，不重试；队友重新派一次后会再试。

## 认领池

认领池用来放**不指定给谁**的任务：谁的电脑有空，谁就领一个去做。

### 怎么用

1. 每台想领活的电脑：**设置 › Agent › 自动接单**选「派给我的，以及认领池」。需要的话改「池标签」（默认 `pool`；只能用小写字母、数字和 `-`，最长 24 个字符）。
2. 把任务放进池里：在共用看板上给任务加上这个标签，状态设成 Ready，负责人留空。
3. 选了认领池也照样接队友直接派给你的任务，和「派给我的」一样。

池里的任务没有派活人，所以「只接」的信任门槛按**最后改标签的那台电脑**来算。自己打的池标签，自己的电脑也能领：池是你特意打标签放进去的，打开开关不会把你自己的任务一下子都开起来。

除了「派给了你」和「不是你派给自己的」这两条，上面「什么时候开工」的其他各条对池里的任务一样适用：Ready、在范围内、是团队任务、没被挡住、还没有 worktree、没有队友在做、信任够、有名额。

### 领、等、确认

1. **领**：对账时，这台电脑在名额允许的范围内，按看板的顺序（状态、优先级、手动排序）挑池里的任务，把负责人改成自己。
2. **等**：领了以后先等 **3 到 7 秒**（3 秒，加上 0–4 秒的随机量），让看板有时间把别人同时的认领合并过来。
3. **确认**：等完再看一眼看板。负责人还是自己，而且任务仍然满足上面各条，就开工（和定向派活一样，「你的 Claude，替打标签的人」开一个 worktree）。负责人已经变成别人，或被清空了，就不开工。

领了还没确认的任务也占名额。比如「同时进行」是 2，已经有 1 个在跑、1 个在等确认，就不会再领新的。

哪些任务在等确认，是从看板上认出来的（带池标签、负责人是你、负责人是你这台电脑改的、还没 worktree）。所以领了以后、确认之前 Beluga 重启了，重启后会重新等一次再确认，只开一次。

改成「派给我的」或「关」以后，不再领池里的任务；已经领了、还在等的也不会开工（这时它就是一个你派给自己的任务，要你自己点 Start）。

### 两台电脑同时领

两台电脑几乎同时领了同一个任务，看板合并「负责人」这个字段时只留一个：改动时间（Lamport 时钟）更新的赢，一样新就按电脑的 id 比。两边很快看到同一个负责人，输的一方确认时发现不是自己，不开工。

### 断网时的代价

两台电脑断开连接时（网络分区）都能领到同一个任务，等完也都还是自己，所以**两边都会开工**，其中一边会白做一段。重新连上后看板合并出一个负责人，输的一方下次对账时：

- 停掉那个 worktree 里的 agent，
- 把 worktree 归档（静默进行，可以从 Archive 恢复，已经做的改动还在）。

每个 worktree 只处理一次。赢的一方不受影响。

只收拾**自动接单开的** worktree：你手动点 Start 开的，负责人变了也不动。负责人被清空（而不是换成别人）时也不动。

## 已知的局限

- 任务的活动记录有条数上限。一个任务活动特别多时，「自动开工」那一行可能被挤掉，名额就少算一个。
- 朋友托你的 Claude 做事（BLG-701）时，如果它通过看板工具开了一个任务，也可能被算成自动开工的。很少见。
- 队友用的是老版本时，派活记录可能显示成你自己派的，任务就不会自动开工。只会少开，不会多开。
- 队友开始或停下做一个任务（「正在做」）时不会马上重新看一眼，等下一次别的变化。
- 认领池等待的 3–7 秒只能挡住「几乎同时」的认领。两台电脑之间消息走得比这更慢时，也可能两边都开工，然后像断网那样由输家收拾。
- 输家是在重新对账时才收拾的（队友改了负责人或状态、有电脑上线等时候），不是一合并就马上停。
