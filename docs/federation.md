# 联邦制：自动接单

几个人一起做一个项目时，每个人的 Beluga 跑在自己的电脑上，用自己的订阅和登录。**自动接单**打开以后，队友在共用看板上把一个任务派给你，你的电脑会自己开工：开一个 worktree，让你的 Claude 按任务的说明去做，不用你先点 Start。

这一页写的是现在已经做好的行为（里程碑 1：定向派活）。认领池（`pool`）还没做。`docs/tasks-and-plans.md` 里「Give it to a teammate's agent…」那一段是旧说法，以这一页为准。

## 前提

- 每台电脑各自装好 Beluga，各自登录 Claude。
- 互相加了好友，并且在同一个 GitHub 仓库上组成了团队，这样看板才是共用的（任务派给谁、状态，都在团队里同步）。
- 每台电脑上项目要用的 `.env` 等密钥由主人自己放好。自动接单不会传任何密钥。

## 怎么打开

Mac：**设置 › Agent › 自动接单**（在 Auto Route 下面）。

| 设置 | 管什么 | 默认 |
|---|---|---|
| 队友派给我的任务自动开工 | 关：什么都不自动开工。派给我的：队友派给你的就绪任务自己开工 | 关 |
| 只接 | 完全信任的人：只有你设成「完全信任」的人派的才开工。信任的人：「信任」和「完全信任」都行 | 完全信任的人 |
| 同时进行 | 自动开工的任务最多同时跑几个，1–6，填别的数会被夹到这个范围里。多出来的留在 Ready 排队，有一个进评审或完成，下一个接着开 | 2 |

这些设置在 `~/.beluga/settings.json` 的 `federation` 里。它们是**这台电脑自己的**：不会随设置同步到你的其他电脑，因为每台电脑能跑多少、信任谁，各不相同。

手机（Beluga Link）不提供这个设置。

**关着时什么都不变**：不监听看板变化，不读看板，不开任何 worktree。和没有这个功能时一模一样。

## 什么时候开工

下面每一条都满足，任务才会自己开工。一个任务没动，就从上往下对一遍，第一条不满足的就是原因：

1. **派给了你**：任务的负责人是你。
2. **状态是 Ready**：Backlog、进行中、评审中、已完成的都不动。
3. **在范围内**：不是私人任务，不在归档里，不属于某个计划（计划的任务由计划自己推进）。
4. **是团队任务**：在和队友共用的看板上，看得出是谁派的。
5. **不是你派给自己的**：你自己把任务派给自己，不会自动开工，还是你自己点 Start。
6. **没被挡住**：它依赖的任务都已进评审或完成。依赖的任务在这台电脑上找不到，也算挡住。
7. **还没有 worktree**：已经开过的不会再开第二个。
8. **没有别人在做**：没有队友正在他们的电脑上做它。
9. **信任够**：派活的人在你这里的信任级别达到「只接」的要求。
10. **有名额**：自动开工、还在进行中的任务数少于「同时进行」。你自己手动开的 worktree 不占名额。

（方案里写的是 8 条；这里把「在范围内」和「不是自己派的」分开写，所以是 10 条。）

## 它什么时候看一眼

队友改了任务派给谁或状态、这台电脑上的任务状态或 worktree 变了、队友的电脑上线、你刚把设置打开、Beluga 启动时。一阵连续的变化只算一次（约 200 毫秒内合并）。

每次都从看板重新算：哪些是自动开工的，从任务的活动记录里认（「你的 Claude，替派活人」把它移到了进行中）。所以 Beluga 重启后不会把同一个任务再开一遍，也照样知道已经占了几个名额。

开工失败（比如刚好有人先开了），只在黑匣子日志里记一行，不重试；队友重新派一次后会再试。

## 已知的局限

- 任务的活动记录有条数上限。一个任务活动特别多时，「自动开工」那一行可能被挤掉，名额就少算一个。
- 朋友托你的 Claude 做事（BLG-701）时，如果它通过看板工具开了一个任务，也可能被算成自动开工的。很少见。
- 队友用的是老版本时，派活记录可能显示成你自己派的，任务就不会自动开工。只会少开，不会多开。
- 队友开始或停下做一个任务（「正在做」）时不会马上重新看一眼，等下一次别的变化。
