单栏版。思路参照腾讯 WorkBuddy 的桌面工作台。

## 1. 一条主线：需求

单位是**一条需求**：从需求单开始，经过理解、计划、批准、开发、交付、验收、上线，下一轮反馈也挂在它下面。客户不
需要知道「需求单」和「计划」是两个对象——侧边栏里它是一行，点开是一条对话，右边是它的成果。

| 阶段（`studio-loop.md`） | 侧边栏 | 说明 |
|---|---|---|
| 分析中、写计划中、开发中 | 绿点「AI 在做」 | — |
| 等回答问题、等确认理解、等批准开工、等批准改动、等验收、等批准上线 | 琥珀点「等你」 | 这几样都是客户自己的事 |
| 排队、执行机器离线、用量已满、需要人看一下 | 灰点「等待」，一句原因 | 会自己恢复或有人来处理；客户不用做什么 |
| 要你亲手处理（密钥过期导致上线失败、交付令牌没权限） | 红点，一句要做什么 | 只有客户自己能修的才用红色 |
| 已通过 | 无点「已完成」 | — |

颜色与用词沿用 M5 §0.4 的状态词汇；「等待」是新的一档，替代原来的「等工作室」。

│              │                                   │                          │
│ [+ 提需求]   │ 标题栏：需求标题 · 状态行  [▣]   │ 产物 | 计划 | 变更 | 预览│

│              │ 你：我想要…                       │                          │

### 2.1 侧边栏

- 顶部 **提需求**（全局快捷键也是它），下面是搜索。它是描边按钮：一屏的实底按钮留给当前这条需求的主动作。
- **「等你」置顶分组**：所有项目里等这个人动手的需求，最紧的在上。这是分层提醒的第一层；第二层是每行的状态点；
  第三层是项目名旁的计数。
- 其余按项目分组，组内按最近活动排序；已完成的折叠在每组末尾的「已完成」里。
- 分组下面是描边的 **新增项目**（§2.5）。一个项目都没有时，列表区的空状态里也是它。
- 底部：头像与 **设置**（§3）。

### 2.2 对话区

- **标题栏**：需求标题（可改）、状态行（M6 §2.5 的那一句）、右端一个按钮展开 / 收起结果区。
- **消息流**：客户与 AI 两种发言（`StudioTurn`；`studio` 发言保留在协议里，本设计没有人用它）。流程上的节点以
  **卡片**嵌在流里，按发生顺序排，往回翻就是这条需求的完整经过：

  | 卡片 | 何时出现 | 上面的动作 | 签名 |
  |---|---|---|---|
  | 设计稿卡 | 客户整包上传了设计稿（`studio-env.md` §9–§13） | 查看 · 查看清单 | — |
  | 问题卡 | 分析或开发中问客户 | 就这样（主）· 每条的「改…」 | — |
  | 理解卡 | 分析写出 `summary` | 就是这样（主）· 继续说 | ✓ |
  | 批准开工卡 | 计划草稿写好 | 开始做（主）· 先不做… · 在结果区看计划 | ✓ |
  | 步骤条 | 开工后 | 每一步一格：待做 / 在做 / 等待 / 已过；点一格在结果区定位 | — |
  | 等待卡 | 排队、执行机器离线、用量已满、需要人 | 无；写明等什么、大概多久、客户要不要做什么 | — |
  | 改动卡 | 「还不行」之后计划有待批准的改动 | 应用改动（主）· 查看 · 放弃在 ••• 里 | ✓ |
  | 交付卡 | 检查通过、预览生成后自动出现 | 通过（主，10 秒撤销）· 还不行… | 通过 ✓ |
  | 代码卡 | 这一轮交付了代码（`studio-forges.md`） | 克隆到本机 · 复制地址 · 重新推送 | — |
  | 上线卡 | 通过后，项目有正式环境（`studio-env.md` §6） | 上线（主）· 先不上… | ✓ |

- **输入框**：一行起、自动增高；📎 附件（桌面可拖入、可截屏标注、可整包拖入设计稿）；手机上多语音与拍照。发出去的
  是 `request.say` 或计划对话，由当前阶段决定，客户不用选。
- **一个主按钮**：输入框下方的动作区永远至多一个实底按钮，就是当前卡片的主动作（延续 M6 的规则）。没有要这个人
  做的事时不显示按钮。带签名的动作，按钮旁的说明里写「由这台设备确认」。

### 2.3 结果区

| 页签 | 内容 |
|---|---|
| **产物** | 卡片：每次交付的预览、安装包、截图、验收说明；可打开、下载；历次交付按轮次分组。下面一组「你提供的材料」：设计稿与附件 |
| **计划** | 计划图 / 大纲 / 动态（M6 已有的三个视图） |
| **变更** | 计划的改动：新增 / 修改 / 移除（`draftDiff`），待批准的标出来。开了代码交付的项目多一栏「代码」：合并请求、状态、检查 |
| **预览** | 当前可看的 Web 预览直接嵌在这里；没有时说明何时会有 |

结果区没有内容时默认收起；有新产物时标题栏按钮上出一个点，不自己弹开打断输入。

### 2.4 提需求页（新建）

一句欢迎语、一个大输入框、下面三个入口：

- **新需求**（默认）：选项目，选平台（iOS / Android / 微信小程序 / Web）。
- **对做好的提意见**：列出这个人能看到的已完成需求，选一个；桌面上可以直接截屏标注。
- **从例子开始**：几条示例需求，点了填进输入框可改。

发出后立刻进入那条需求的对话，侧边栏多一行「AI 在做」。可以马上再提下一条，互不等待。

### 2.4a 问题只有一种交互：确认

问题是**这个项目、这件事**的问法，由 AI 写在正文里；卡片不为具体问题做选项、药丸、单选，也不为某类问题单画界面。
所有问题统一成一种交互，让客户来**确认**：

- AI 对每个问题**先给一个建议答案**（「我先按：15 分钟后」），不给出选项让客户挑。
- 客户点底部的主按钮 **就这样** 整体确认，或在某一条上点 **改…**，在原地写一句（可以语音），其余条仍按建议。
- 一次最多三条；拿不准就直接在对话里说，不用点卡。
- 确认后，AI 把答案写成「我们的理解」卡，客户再确认一次（理解卡）。

数据上仍沿用 `StudioDecision`：把第一个选项当建议答案，「改…」就是自己写；协议不改，客户端不按选项渲染控件。
画稿：手机 P3、桌面 C 页「回答问题」，组件规范里的「问题卡」。

### 2.5 新增项目

项目由客户自己新增，不用等搭环境的人。三个入口，进的是同一个页面（桌面是对话框）：

- **提需求页**：「项目」下拉的最后一项「新增项目…」。建好后回到提需求页，并选中新项目，输入的内容不丢。
- **我 › 项目与代码交付**（桌面：设置 › 项目）：列表底下的「新增项目」一行。
- **需求页还没有项目时**：空状态里的「新增项目」。侧边栏分组下面也有一个，桌面常驻。

上面一个分段：**空项目**（默认）、**从仓库导入**。

- **空项目**：填 **项目名称**、**做什么**（iOS / Android / 微信小程序 / 网页，可多选）。底下一个实底按钮「创建项目」。
- **从仓库导入**：两个登录按钮，**用 GitHub 登录**、**用 cnb.cool 登录**；登录后列出这个人的仓库，可搜索，选一个，
  项目名称默认取仓库名，可改；平台自动按仓库猜，可改。底下实底按钮「导入并创建」，旁边写「令牌只发给你的执行机器，
  我们的服务器看不到；由这台手机确认」。导入要设备签名；cnb.cool 的登录还没审核下来时，这里先让客户贴访问令牌。

数量**不设上限**。代码交付默认只给预览（导入的项目也是），之后在设置里改。空项目**不签名**。

创建后项目几秒内出现（导入看仓库大小，行上写进度），可以马上提需求。节点还没准备好时，项目行写「正在准备」、灰色点，
写明「你不用做什么」，不显示失败。导入失败（令牌过期、没有权限）写成客户能改的话，红色只给这种。
放在哪台节点、怎么建，见 `studio-standalone.md` §4.7。画稿：手机 P13（空项目）、P13b（从仓库导入）、P14，桌面「4 · 新增项目」。

## 3. 设置

头像 › 设置。左边一列分页，右边内容。签名的改动在保存按钮旁写「由这台设备确认」。

| 页 | 内容 | 写入 |
|---|---|---|
| **项目** | 每个项目的平台、默认运行方式（每一步都验收 / 全自动，交付时验收一次） | 签名 |
| **环境与密钥** | 测试 / 预发 / 正式三个环境：上线到哪里、变量、密钥（`studio-env.md`） | 签名；密钥封给节点 |
| **代码交付** | 只给预览 / 给仓库 / 推到我的仓库；仓库与令牌（`studio-forges.md`） | 签名；令牌封给节点 |
| **执行机器** | 几台、在不在线、能不能接、正在做哪几条需求、本月用量（`studio-standalone.md` §6） | 只读 |
| **设备** | 已登记的设备；加一台设备（出二维码）、移除 | 签名 |
| **账号** | 邮箱、通知、外观、退出登录、删除账号 | 会话 |

执行机器只读：加机器、改上限在节点上用 CLI 做（`studio-standalone.md` §5.1、§7），客户改不了自己的刹车。

## 4. 手机

同一套内容，单栏：

- 底部三个页签：**需求**（就是桌面的侧边栏，「等你」置顶）、**待办**（所有等你的卡片，最紧的在上；下面一组「在
  等待，你不用做什么」）、**我**（设置的手机版）。
- 点一条需求进对话；结果区变成从底部拉起的抽屉，四个页签不变（M6 已有抽屉组件）。
- 提需求：输入框旁有语音和拍照；拍下的照片与截屏一样当附件；设计稿包从「文件」里选。
- 批准开工、通过、批准上线在手机上都能做，由这台手机的设备密钥签名。
- 环境与密钥在手机上只读（名字、更新时间、更新人）；填和换在桌面或 Web。
- 通知的按钮可以直接「去看看」，签名的动作都要点进应用再做，不在通知上直接批。
- 版式、间距、文案以 M5、M6 为准；新增的卡片按 M6 的卡片规格做。

## 6. 视觉

沿用 `packages/companion/lib/theme.ts` 的 token 与 `CLAUDE.md` 的规则：柔和的浅色与图标，不用发光与霓虹；标题栏与
工具栏是实底，滚动后一条细线，不用渐变；一屏一个主动作，其余进 ••• 或设置。桌面三栏之间用细线分隔，不用阴影
堆叠。

画稿时补定的几条：

- **一屏至多一个实底按钮。** 桌面侧边栏的「提需求」因此是描边按钮。
- **否定的动作与主动作分开。** 动作区里「还不行…」「先不做…」靠左，主动作靠右，中间一句后果说明。
- **表格里时间和人各占一列**，不用圆点拼成一句。
- **灰底上的说明文字用 `#6A6A70`**（对比 5.0）；`text3` 的 `#737379` 只用在白底上（灰底上只有 4.4）。
- **桌面字号**：正文 14、次级 13、说明 12、标题 16、大标题 26。手机仍以 `theme.ts` 为准。
- **窗口宽度**：≥ 1160 三栏并排；900–1159 结果区盖在对话区上；< 900 用手机版式。1160 是提议，待定。

### 6.1 交互

规则参照 VoiceBridge（畅译 2.0）iOS 组件库的做法；只借规则，不借它的玻璃材质与回弹手感。稿里是「规范 交互」一页。

| 规则 | 做法 |
|---|---|
| 能反悔的用撤销，不弹确认 | 通过交付（10 秒）、应用改动、移除附件、删变量：直接做，给一条撤销条。同时只有一条，新的替换旧的；写清做了什么和对象的名字。签名的动作在撤销时间过后才发出 |
| 不可逆才二次确认 | 删密钥、移除设备、放弃全部改动、批准上线、删除账号。确认框的主按钮写动作名 |
| 带「…」的按钮先问原因 | 还不行…、先不做…、先不上… |
| 主按钮自己显示进度 | 空闲 → 进行中 → 完成三态；进行中不能再点、宽度不变；失败回到空闲并在旁边说原因 |
| 推迟写「等待」，不写「失败」 | 执行机器离线、排队、用量已满、需要人：写「等待」、用灰色，步骤条那一格画斜纹。红色只给客户亲手能修的事 |
| 原地提示，不锁页面 | 没有预览、执行机器离线、设计稿没传完：在那一块的位置说原因与何时会好，不弹窗、不遮罩 |
| 按钮只写动作 | 后果写在按钮旁边的一句说明里 |
| 抽屉手势 | 下拉跟手；拖过三成或甩得够快关闭；点遮罩关闭；内容超高时在抽屉内滚动；抽屉开着时底部页签让位 |
| 输入法不误发 | 拼音组字中按回车只上屏、不发送；发送键与回车走同一条路 |
| 动效可打断 | 从当前位置重新出发；系统开了减弱动态效果就直接到位；列表出现时每项错开 60 ms，最多 5 项 |
| 读屏 | 自绘的页签与分段保留系统控件的语义；撤销条与状态变化礼貌朗读，焦点不跳走 |
| 手机触感 | 切页签用选择反馈；通过、开始做、上线成功一下；出错一下警告；还不行、取消、撤销没有。一次动作最多一下 |
