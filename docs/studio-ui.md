## 1. 一条主线：需求

WorkBuddy 的单位是「任务」。Studio 的单位是**一条需求**：从需求单开始，经过理解、计划、开发、交付、验收，下一轮
反馈也挂在它下面。客户不需要知道「需求单」和「计划」是两个对象——侧边栏里它是一行，点开是一条对话，右边是它的
成果。

| 阶段（`studio-loop.md`） | 侧边栏状态 | 等谁 |
|---|---|---|
| 分析中、写计划中、开发中 | 绿点「AI 在做」 | AI |
| 等回答问题、等确认理解、等验收 | 琥珀点「等你」 | 客户 |
| 等批准开工、等确认交付 | 灰点「等工作室」（你的视角里是琥珀「等你」） | 你 |
| 已通过 | 无点「已完成」 | — |
| 节点离线、分析失败、排队超时 | 红点，一句原因 | 你 |

颜色与用词沿用 M5 §0.4 的状态词汇，不新增。

### 2.1 侧边栏

- 顶部一个主按钮 **提需求**（全局快捷键也是它），下面是搜索。
- **「等你」置顶分组**：所有项目里等这个人动手的需求，最紧的在上。这是分层提醒的第一层；第二层是每行的状态点；
  第三层是项目名旁的计数。出问题的需求（红点）也进这一组。
- 其余按项目分组，组内按最近活动排序；已完成的折叠在每组末尾的「已完成」里。
- 底部：头像（账号、身份切换、设置）。同一个账号既是某工作室的主人、又是别处的客户时，在这里切换视角；两种视角的
  数据不混在一个列表里。
- 主人视角多三个固定入口，在搜索下面：**收件箱**（等我批准、等我交付、没人接）、**节点**、**客户与项目**。

### 2.2 对话区

- **标题栏**：需求标题（可改）、状态行（M6 §2.5 的那一句）、右端一个按钮展开 / 收起结果区。
- **消息流**：客户、AI、工作室三种发言（`StudioTurn`）。流程上的节点以**卡片**嵌在流里，按发生顺序排，往回翻就是
  这条需求的完整经过：

  | 卡片 | 何时出现 | 上面的动作 |
  |---|---|---|
  | 理解卡 | 分析写出 `summary` | 就是这样（主）· 继续说（回到输入框） |
  | 问题卡 | 分析或开发中问客户 | 选项 / 自由回答 |
  | 计划卡 | 草稿写好 | 在结果区打开计划 |
  | 等待卡 | 等工作室批准开工 / 批准改动 | 无（主人视角：批准 · 不批准…） |
  | 步骤条 | 开工后 | 每个里程碑一格：待做 / 在做 / 已过；点一格在结果区定位 |
  | 改动卡 | 计划有待确认的改动 | 应用改动（主）· 查看 · 放弃在 ••• 里 |
  | 交付卡 | 你确认交付后 | 通过（主，10 秒撤销）· 还不行… |
  | 代码卡 | 这一轮交付了代码（`studio-forges.md`） | 克隆到本机 · 复制地址 |
  | 设计稿卡 | 客户整包上传了设计稿（`studio-env.md` §9–§13） | 查看 · 查看清单 |
  | 提供密钥卡 | 你向客户要一把密钥（`studio-env.md` §5） | 填入（填完后谁都看不到） |

  等待卡上写明等谁、通常多久（取自你在项目里填的承诺时间）、客户要不要做什么。

- **输入框**：一行起、自动增高；📎 附件（桌面可拖入、可截屏标注）；手机上多一个语音键。发出去的是
  `request.say` 或计划对话，由当前阶段决定，客户不用选。
- **一个主按钮**：输入框下方的 ActionDock 永远至多一个实底按钮，就是当前卡片的主动作（延续 M6 的规则）。没有要这个
  人做的事时不显示按钮。

### 2.3 结果区

四个页签，对应 WorkBuddy 的「产物 / 全部文件 / 变更 / 预览」，内容换成 Studio 的：

| 页签 | 客户看到 | 你多看到 |
|---|---|---|
| **产物** | 卡片：每次交付的预览、安装包、截图、验收说明；可打开、下载；历次交付按轮次分组 | 「加预览」入口；每个产物给没给客户 |
| **计划** | 计划图 / 大纲 / 动态（M6 已有的三个视图） | 任务 KEY、预估、在哪个节点、检查结论 |
| **变更** | 计划的改动：新增 / 修改 / 移除（`draftDiff`），待确认的标出来 | 另加一栏「代码」：合并请求列表、状态、检查；点开跳到托管平台 |
| **预览** | 当前可看的 Web 预览直接嵌在这里；没有时说明何时会有 | 同左 |

结果区没有内容时默认收起；有新产物时标题栏按钮上出一个点，不自己弹开打断输入。

### 2.4 提需求页（新建）

点「提需求」后中间一栏是：一句欢迎语、一个大输入框、下面三个入口——

- **新需求**（默认）：选项目，选平台（iOS / Android / 微信小程序 / Web）。
- **对已交付的提反馈**：列出这个人能看到的已完成需求，选一个；桌面上可以直接截屏标注。
- **从例子开始**：几条示例需求，点了填进输入框可改。

发出后立刻进入那条需求的对话，侧边栏多一行「AI 在做」。可以马上再提下一条，互不等待。

## 3. 主人视角多出的屏

| 屏 | 内容 | 主动作 |
|---|---|---|
| **收件箱** | 三段：等我批准开工、等我确认交付、没人接的需求（附原因）。每行是一张压缩的卡 | 行内直接批准 / 交付；要细看就点进那条需求 |
| **节点** | 每台节点：名字、在线、能不能接（不能的原因）、空位、正在跑的需求；可信设备列表 | 配对新设备 · 撤销 · 把某条未开工的需求换节点 |
| **客户与项目** | 项目、成员、每个项目映射到哪些节点、默认运行方式、代码交付方式；**环境**页签：上线目标、变量、密钥（`studio-env.md`） | 邀请客户 · 发登录链接 |
| 需求里的 **和客户说** | 输入框上的一个切换：默认是「内部备注」（只进 agent 的上下文），切到「发给客户」才成为工作室发言 | — |

批准与交付在三个地方都能做（收件箱、对话里的等待卡、系统通知的按钮），是同一个签名动作（`studio-standalone.md`
§5）。

## 4. 手机

同一套内容，单栏：

- 底部三个页签：**需求**（就是桌面的侧边栏，「等你」置顶）、**待办**（M6 的待办屏；主人视角就是收件箱）、**我**。
- 点一条需求进对话；结果区变成从底部拉起的抽屉，四个页签不变（M6 已有抽屉组件）。
- 提需求：输入框旁有语音和拍照；拍下的照片与截屏一样当附件。
- 通知的按钮可以直接「通过 / 批准」，其余动作点进应用。
- 版式、间距、文案以 M5、M6 为准，本文不重写；新增的卡片（理解卡、交付卡、代码卡）按 M6 的卡片规格做。

## 6. 视觉

沿用 `packages/companion/lib/theme.ts` 的 token 与 `CLAUDE.md` 的规则：柔和的浅色与图标，不用发光与霓虹；标题栏与
工具栏是实底，滚动后一条细线，不用渐变；一屏一个主动作，其余进 ••• 或设置。桌面三栏之间用细线分隔，不用阴影
堆叠。

画稿时补定的几条（稿在 Claude Design 项目「Synon Studio 工作台」，共 9 页 38 屏，含框架、VI、组件与走查）：

- **一屏至多一个实底按钮。** 桌面侧边栏的「提需求」因此是描边按钮，实底留给当前这条需求的主动作。
- **否定的动作与主动作分开。** 动作区里「还不行…」「不批准…」靠左，主动作靠右，中间留空。
- **表格里时间和人各占一列**，不用圆点拼成一句。
- **灰底上的说明文字用 `#6A6A70`**（对比 5.0）；`text3` 的 `#737379` 只用在白底上（灰底上只有 4.4）。
- **桌面字号**：正文 14、次级 13、说明 12、标题 16、大标题 26。手机仍以 `theme.ts` 为准。
- **窗口宽度**：≥ 1160 三栏并排；900–1159 结果区盖在对话区上；< 900 用手机版式。1160 是提议，待定。

### 6.1 交互

规则参照 VoiceBridge（畅译 2.0）iOS 组件库的做法；只借规则，不借它的玻璃材质与回弹手感。稿里是「规范 交互」一页。

| 规则 | 做法 |
|---|---|
| 能反悔的用撤销，不弹确认 | 通过交付（10 秒）、应用改动、移除预览、删变量：直接做，给一条撤销条。同时只有一条，新的替换旧的；写清做了什么和对象的名字 |
| 不可逆才二次确认 | 删密钥、移除客户、撤销设备、放弃全部改动、删除项目。确认框的主按钮写动作名 |
| 带「…」的按钮先问原因 | 还不行…、不批准…、还不能交付… |
| 主按钮自己显示进度 | 空闲 → 进行中 → 完成三态；进行中不能再点、宽度不变；失败回到空闲并在旁边说原因 |
| 推迟写「等待」，不写「失败」 | 节点离线、排队、用量上限：客户屏写「等待」、用灰色，步骤条那一格画斜纹。红色只在主人屏、且要主人动手时出现 |
| 原地提示，不锁页面 | 没有预览、工作室离线、设计稿没传完：在那一块的位置说原因与何时会好，不弹窗、不遮罩 |
| 按钮只写动作 | 后果写在按钮旁边的一句说明里 |
| 抽屉手势 | 下拉跟手；拖过三成或甩得够快关闭；点遮罩关闭；内容超高时在抽屉内滚动；抽屉开着时底部页签让位 |
| 输入法不误发 | 拼音组字中按回车只上屏、不发送；发送键与回车走同一条路 |
| 动效可打断 | 从当前位置重新出发；系统开了减弱动态效果就直接到位；列表出现时每项错开 60 ms，最多 5 项 |
| 读屏 | 自绘的页签与分段保留系统控件的语义；撤销条与状态变化礼貌朗读，焦点不跳走 |
| 手机触感 | 切页签用选择反馈；通过、批准、交付成功一下；出错一下警告；还不行、取消、撤销没有。一次动作最多一下 |
