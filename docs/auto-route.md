# 自动路由(Auto route)

本分叉新增的功能。任务启动时，如果没有人给它指定 agent,Beluga 会按任务的难度自动挑一个模型。规则写在 `src/shared/auto-route.ts`。

## 谁来做这个任务

依次检查下面几项，用第一个有结果的:

1. 这次启动时选的 agent(Start with ▸)。
2. 任务自己的 agent。
3. 任务所属 Plan 的 agent。
4. 项目的 agent(项目设置里指定的)。
5. 自动路由选出的模型。
6. 你的默认 agent。

自动路由只在有 agent 开始做这个任务时计算(只建 worktree 不算，那样仍用你的默认 agent),结果不写进任务。所以团队看板上的队友不会收到只有你这台 Mac 才有的 endpoint。

跨仓库的 epic:其他仓库的 worktree 也用同一个自动选出的模型，但那个仓库设了自己的项目 agent 时，用它自己的。

注意：标签和优先级是看板上共享的。队友把任务标成 `hard` 或紧急、高，你的 Mac 启动它时就会用疑难档(比如你 API key 上的 Opus)。

## 规则

| 档位 | 条件 | 默认候选，依次尝试 |
|---|---|---|
| 疑难 | 带 `hard` 标签，或优先级为紧急、高，或估点 ≥ 5 | `local:anthropic/claude-opus-5-5`(API key)→ `claude:opus`(订阅) |
| 其他 | 其余所有任务 | `local:bigmodel/glm-5.3[1m]` → `local:deepseek/deepseek-flash[1m]` → `local:anthropic/claude-haiku-5-5` → `claude:haiku` |

- 每档取第一个在本机可用的候选。可用的标准和 agent 选择器一致：运行时已配置;local endpoint 列出了这个模型，并且正在应答。选择器里灰掉的候选会被跳过。
- 某一档的候选全部不可用时，交给你的默认 agent,和以前一样。

## 和 Plans 一起用：自动拆、自动选、自动推进

自动路由开启时:

- **新 Plan 默认用 Autopilot**:在对话里开 Plan,或在 Plans、项目首页新建时，默认选中 Autopilot,按里程碑自动推进，只有出错才停。你仍然可以在创建时改成别的。
- **Plan 拆出的任务按估点分档**:Plan 负责人给每张任务卡估 1、2、3 或 5 点。估点 ≥ 5 的任务走疑难档(Opus),其余走 GLM 那一档。阈值可以在 `settings.json` 的 `autoRoute.hardEstimate` 里改，设为 0 表示不按估点判断。
- **里程碑由 Sonnet 审计**:Plan 没有指定审计 agent,也没有指定工作 agent 时，里程碑检查和草稿审查用审计列表(`review`,设置 › 自动路由 › 计划审计)的第一个(Sonnet)。指定了的话用你指定的。
- **疑难交给修复模型**:Plan 没有指定疑难修复 agent 时，验收不过后的修复任务、冲突、停了两次的任务交给疑难档的第一个(Opus);自动路由关着时照旧，留给原来的 agent。

注意:Plan 设了自己的工作 agent 时，它的所有任务都用那个 agent,自动路由会让位。想让每个任务按需求选模型，Plan 的 agent 留空。

## 让任务能带上 `hard` 标签

默认标签里没有 `hard`。在任务看板的项目标签里加一个名为 `hard` 的自定义标签。之后 drafter 写任务时如果判断它难，会自己打上这个标签，你也可以手动加。

## 设置

Settings › Agent › 自动路由:

- 开关：没有手动设置过时，只要列表里有一个 `local:` 候选在本机可用(比如 GLM、DeepSeek 或 API key 上的 Anthropic 模型)就默认开启。只用 Claude 订阅或只开着 Ollama 的 Mac 保持原来的行为，需要手动打开。
- 紧急和高优先级是否也算疑难。
- 两档的候选列表：可以换模型、调整顺序、添加、删除、恢复默认。

设置保存在 `settings.json` 的 `autoRoute` 字段，会同步到你的其他电脑。某台电脑上没有的候选会自动跳过。

疑难标签的名字默认是 `hard`,想换成别的，可以在 `settings.json` 的 `autoRoute.hardLabel` 里改，设置面板里没有这一项。

## 在哪里能看到

- Mac:任务页的 Start、任务右键菜单的提示里显示"自动 · Opus 5.5"。
- 手机：任务页显示"Auto · …"(协议 1.51,`TaskPageView.autoAgent`)。

## 碰到用量额度：换到同一档的下一个模型

计划里的任务因为用量额度停下时(比如 GLM 的接入点返回 429),不再原地等额度恢复:它的对话立刻换到**同一个列表里的下一个模型**,并马上继续。规则在 `src/fork/plans/same-tier.ts`:

- 只在同一档里换:编码任务列表里的 GLM 到了额度,换给 DeepSeek,不会升到 Opus。
- 跳过共用同一个额度的模型:同一个接入点的其他模型、同一个 Claude 登录下的其他模型。
- 跳过本机跑不了的和自己也在额度中的;排在后面的先试，再试排在前面的。
- 换过去之后就留在那个模型上(同一档，没有换回的必要)。在额度恢复之前开工的新里程碑，也从下一个模型开始。
- 没有可换的(列表里只剩共用额度的模型)、模型不在任何列表上、用的是默认 agent、或自动路由关着:和以前一样，等额度恢复后自动继续。
- 「额度恢复后自动继续」关掉时(设置、这个对话或这次会话),不会自动换模型，等你处理。

对话卡片上，接入点的额度写作「这个模型的接入点已达到用量额度」,不再写成 Claude 套餐的额度。

还没做的:

- 计划以外的任务(直接在任务页点 Start 的)碰到额度时不会换模型，只会等恢复。
- 额度状态只记在这次运行里，Beluga 重启后会重新试一次原来的模型。

模型报错(找不到模型、Key 被拒)时沿梯子升级，见 `docs/fork.md` 的「模型失效的升级梯子」。

注意:local 运行时会把子代理的模型也设成同一个模型(`src/agent/runtime/local.ts` 的 `endpointEnv`),所以模型分工只能做在任务层面。
