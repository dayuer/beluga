# 界面多语言（第一版：框架 + Mac 主界面中文）

日期：2026-11-09 · 分支：`ui-i18n`

## 目标

Mac 应用的高频界面可以用简体中文显示，并为之后的手机端和引擎文字打好地基。默认跟随 macOS 系统语言。

## 不在本版

- macOS 原生菜单栏（`packages/mac/src-tauri/src/menu.rs`，Rust）：需要单独的方案。
- 手机端（`packages/companion`）。
- 引擎生成的文字：toast、plan 和 task 的动态记录、通知、`plans.setWorkAgent` 这类 API 返回的句子。它们由 `src/core` 生成，有的已经以英文存进了历史记录，需要先改造成"消息 key + 参数"的形式，留到后续批次。
- agent 的回复语言：跟随用户提问时用的语言，本版不处理。

## 设置

- 存放在 Mac 本机的界面偏好 `UiPrefs.language` 里（`packages/mac/src/lib/prefs.ts`，localStorage），可选值为 `'system' | 'en' | 'zh-CN'`，默认 `system`。外观（appearance）也存在这里。（实现时修订：原计划放进 daemon 的共享设置，但语言和外观一样，是"这块屏幕怎么显示"，放在本机更合适，也不用改 daemon 和 API。等以后翻译引擎生成的文字时，再把语言同步给 daemon。）
- `prefs.apply()` 会同步设置 `<html lang>`。
- 入口：Settings › Appearance › Language，选项为"跟随系统 / English / 简体中文"。`settings-index.ts` 的搜索关键词加上 `language 语言 中文`。
- 切换后立即生效，不用重启。

## 框架：`src/shared/i18n.ts`（只用浏览器 API，无新依赖）

```ts
export type Locale = 'en' | 'zh-CN';
export type Dict = Record<string, string | ((v: Record<string, string | number>) => string)>;
export function resolveLocale(setting: 'system' | Locale, system: readonly string[]): Locale;
export function makeT<D extends Dict>(en: D, dicts: Partial<Record<Locale, { [K in keyof D]: D[K] }>>): (locale: Locale) => <K extends keyof D>(key: K, vars?: …) => string;
```

- `resolveLocale`：设置为 `en` 或 `zh-CN` 时直接用它。设置为 `system` 时，取 `navigator.languages` 中第一个以 `zh` 开头的项，`zh-Hans`、`zh-CN`、`zh-TW` 都返回 `zh-CN`，其余情况返回 `en`。
- 插值写法是 `{name}`。如果某个 key 没有对应的变量，原样保留 `{name}`，方便测试发现问题。
- 字典的值可以是函数，用来处理英文要随数量变化的句子。中文直接写一句即可。
- 日期、数字和相对时间用 `Intl`，传入当前 locale。

## Mac 端的接入

- `packages/mac/src/i18n/en.ts` 是源文件，`as const` 导出，key 按页面分组命名，例如 `sidebar.projects`、`settings.appearance.language`。
- `packages/mac/src/i18n/zh-CN.ts` 的类型是 `{ [K in keyof typeof en]: … }`，**缺少任何一个 key 都会导致 typecheck 失败**。
- `packages/mac/src/i18n/index.ts` 导出：
  - `useT()`：在 React 组件里使用，从 store 的设置读出 locale；
  - `t()`：模块级函数，供菜单模型这类非组件代码使用，读当前 locale；
  - `setLocale()`：设置变化时由 `App.tsx` 调用，然后根组件重新渲染。
- 术语表（固定译法）：

| 英文 | 中文 |
|---|---|
| Plan / Milestone / Task | 计划 / 里程碑 / 任务 |
| Worktree / Branch / Merge / PR | 工作树 / 分支 / 合并 / PR |
| Agent / Autopilot / Check-ins / Step by Step | Agent / 自动驾驶 / 阶段确认 / 逐步 |
| Sentinel / Approval / Needs you | 哨兵 / 审批 / 等你处理 |
| Beluga、Claude、Codex、OpenCode | 不翻译 |

  语气：简短、口语化，和英文版的风格保持一致。按钮用动词，不加句号。

## 第一批迁移的界面

1. 侧栏和顶部（`layout/`）：项目列表、分区标题、浏览器里的应用菜单（`lib/app-menu-model.ts`）。
2. Settings 对话框（`dialogs/`）：各分区的标题、选项和说明。
3. 输入框和 agent 选择器（`chat/` 中的 Composer、ModelPicker、`components/agent-options.ts`）。
4. 对话中的按钮和状态行（`chat/`）：停止、继续、审批卡片的按钮等。
5. Plans 和 Tasks 页面（`plans/`、`tasks/`）：按钮、菜单、空状态。
6. 通用的确认框和弹窗（`dialogs/`）。

其余页面保持英文，后续分批迁移。每一批都要遵守同一条规则：动到的字符串必须全部进字典。

## 测试

- `tests/i18n.test.ts`：
  - `resolveLocale` 的各种情况（system 下的 zh-Hans、zh-TW、en-US、空列表）；
  - 插值和缺失变量；
  - 函数值；
  - 在 Node 环境（测试）下固定为英文，不受本机 locale 影响。
- 中文字典完整：由 Mac 的 typecheck（在 `packages/mac` 里运行 `npm run typecheck`）保证。
- e2e：`packages/mac/e2e` 的现有用例把 locale 固定为 `en`，截图不变。新增一个用例：切换到简体中文后，侧栏和 Settings 显示中文。

## 完成标准

- 设置为简体中文时，第一批的 6 类界面没有残留英文。产品名、用户自己的内容、引擎生成的句子除外。
- 设置为 English 时，界面和现在完全一样，e2e 截图不变。
- `npm run typecheck`、`npx vitest run` 和 Mac 的 typecheck 全部通过。
