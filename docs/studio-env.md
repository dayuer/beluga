# 项目环境、密钥与设计稿上传（设计稿）

状态：**设计稿，未实施，未审计**。两件事写在一篇里，因为它们都要回答同一个问题：**客户和你交给 Studio 的东西
（密钥、设计稿）存在哪、谁读得到**。

- 第一部分：在 Studio 里维护每个项目的上线环境、变量与密钥，以及正式环境上线的批准。
- 第二部分：提需求时把设计稿整包上传。

先读：[`studio-standalone.md`](studio-standalone.md)（节点、设备密钥与签名，§5）、[`studio-loop.md`](studio-loop.md)
（需求单、预览上传，§5.2）、[`studio-forges.md`](studio-forges.md)（令牌存在节点上，§4）、
[`studio-terms.md`](studio-terms.md)（中台存什么）。界面见 [`studio-ui.md`](studio-ui.md)；画好的屏在 Claude Design
项目「Synon Studio 工作台」的「工作台 项目环境」「工作台 状态与补充」「手机 全流程」三页。

## 0. 结论摘要

- **环境与密钥的归属是节点，不是中台。** 定义和值都存在负责上线的那台节点上；中台只转发，主人视图里只有名字、
  用途、更新时间、更新人。
- **密钥的值端到端加密到节点。** 在你的设备上用节点的公钥封好再发，中台与动作队列里只有密文。这样
  `studio-terms.md`「中台永远不存密钥」可以原样保留。
- **密钥只写不读。** 界面上没有查看、没有复制；节点也不提供读回的接口，只提供「换」和「删」。
- **正式环境上线是第三道 Gate**（`release`），和开工、交付一样由设备密钥签名。
- **设计稿包存在中台的对象存储里**，和 P2 的预览产物同一套（`studio-loop.md` §5.2）。它不是密钥，但会被中台读到，
  条款要补一行。压缩包在客户端解开，中台和节点都不解压。
- 这两部分都只做加法，`STUDIO_PROTO.major` 不动。

## 第一部分：环境与密钥

### 1. 模型

```ts
// 只在主人视图（operator）里；客户视图里完全没有
StudioEnvView = {
  id: string,                      // 'test' | 'staging' | 'prod' 起步，可改名、可删到只剩两个
  title: TITLE,                    // 测试 / 预发 / 正式
  protected: boolean,              // true：上线要过 release Gate，AI 的 run 拿不到这里的密钥
  target: { platform: Platform, appId?: string /* 中间打码 */, mode: TEXT },
  nodeId: string,                  // 由哪台节点上线；密钥就封给它
  vars:    { name: NAME, value: TEXT, at: int, by: WHO }[],
  secrets: { name: NAME, purpose: TEXT, at: int, by: WHO, staleDays?: int }[],   // 没有 value
  lastRelease?: { version: TEXT, at: int, by: WHO },
}
WHO = { role: 'studio' | 'customer', name: TITLE }
```

- `at`（时间）与 `by`（人）是两个字段，界面上也是**两列**，不拼成一句。
- `NAME` 只收 `[A-Z][A-Z0-9_]{0,63}`；`value` 上限 4 KB，密钥明文上限 16 KB（证书、私钥文件够用）。
- 变量是非机密的（接口地址、开关）：值进主人视图，过 `redactSecrets`，长得像密钥的拒收并提示「这个应该放进密钥」。
- 落盘：节点上 `studio-env.json`（0600），密钥的值进系统钥匙串，没有钥匙串的无窗口节点用 0600 文件。按项目隔离，
  随项目删除而删除。不进 store、不进视图、不进日志。

### 2. 密钥怎么从你的设备到节点

1. **节点有自己的一对密钥**（X25519），第一次连接 Studio 时生成，私钥不离开那台机器。
2. **你的设备怎么拿到节点的公钥**：走已有的配对与信任通道（`studio-standalone.md` §5）。配对时节点把自己的公钥
   连同配对帧一起给设备；之后新加的节点，公钥经「Your settings follow you」的端到端通道同步到已信任的节点，再由
   它们签名后告诉设备。**中台不是公钥的来源**，所以换不了钥。
3. **封装**：设备用节点公钥把值封成 sealed box，发
   `env.setSecret{projectRef, envId, name, purpose, sealed, toKey /* 节点公钥指纹 */, at}`，整帧用设备密钥签名
   （与 `gate.answer` 同一套验签与防重放）。
4. **中台**只看到密文，照常进动作队列（节点离线时最多留 7 天）。队列里是密文，不改变「不存密钥」这句话。
5. **节点**验签、查设备在信任名单里、核对 `toKey` 是自己，解开，写入钥匙串，回执 `done`；视图里这一行的 `at` 与
   `by` 更新。

换节点（`nodeId` 变了）：密钥不会自己跟过去。两种做法，见待定 2。

### 3. 动作（都只给主人，除 §5）

| 动作 | 载荷 | 签名 | 结果 |
|---|---|---|---|
| `env.put` | `{projectRef, envId, title?, target?, nodeId?, protected?}` | 是 | 建或改一个环境 |
| `env.setVar` | `{projectRef, envId, name, value}` | 否 | 写变量 |
| `env.delVar` | `{projectRef, envId, name}` | 否 | 删变量 |
| `env.setSecret` | 见 §2 | 是 | 写或换密钥 |
| `env.delSecret` | `{projectRef, envId, name}` | 是 | 删密钥 |

没有 `env.getSecret`，协议里不留这个名字。

### 4. 谁用得到这些值

| 用的地方 | 变量 | 非 `protected` 环境的密钥 | `protected` 环境的密钥 |
|---|---|---|---|
| AI 的开发与检查 run | 可以（进环境变量） | 逐个开「给 AI 用」才可以，默认关 | **永远拿不到** |
| 客户回合（分析、规划） | 不给 | 不给 | 不给 |
| 上线步骤 | 可以 | 可以 | 可以，且只在 release Gate 通过后 |

上线步骤本身（上传小程序代码、发 TestFlight、部署 Web）是节点上的脚本，每个平台的适配另写；本文只定配置从哪来、
谁批准。脚本的输出过 `redactSecrets` 后才进主人视图，并且把这次注入过的值逐个加进脱敏名单。

### 5. 客户自己的密钥

小程序 AppID、支付商户密钥、推到客户仓库的令牌（`studio-forges.md` §3.2）通常在客户手里。不让客户把它贴进对话
——对话的文字会进中台、进 agent 的上下文。

- 你在环境页点 **向客户要这把密钥**，选客户、写清用途 → 客户那边出一张「提供密钥」卡（对话里和待办里）。
- 客户填一次，设备上封给节点，发 `secret.provide{secretRequestRef, sealed, toKey}`（进客户动作白名单）。填完后客户
  自己也看不到；环境页这一行的更新人记客户的名字。
- 客户没有配对通道，他拿到的节点公钥**只能经中台**。所以中台被攻破时可以换钥、截下这把密钥。两种缓解，见待定 3。

### 6. 上线 Gate

```ts
StudioGate.kind 追加 'release'
```

- 只有 `protected` 环境要过。测试环境可以在交付时由节点自己发（这就是今天「体验版已更新」的来历）。
- 卡上有：环境、要上的版本（交付标签 `delivery/<n>`）、上次上线的版本与时间、检查结论。动作 **上线**（主，签名）与
  **先不上…**（写原因）。
- 客户通过交付之后才升起；一个环境同一时间只有一张。
- 过渡期如果 Beluga 里也出这张卡（`studio-release`），按 `CLAUDE.md` 它是新的「等你」的东西，要作为 `NeedsYou` 到
  手机并通知。

### 7. 界面

位置：**客户与项目 → 选项目 → 环境**（`studio-ui.md` §3）。上面一排分段选环境；下面三块：上线到哪里、变量、密钥。

- 表格的列：名称、值或用途、**更新时间**、**更新人**、动作。时间和人各占一列。
- 密钥的值永远画成圆点。动作只有「更换」，删除在 ••• 里。超过 90 天没换的密钥在用途旁标一句，节点本地算，不发提醒。
- 这一页不放实底按钮：没有「等你做」的事。实底按钮只在 release 卡上。
- 手机：只读名称、用途、更新时间、更新人；填和换只在桌面与 Web 做。release 卡在手机上可以批。
- 客户看不到这一页，只在被要密钥时看到那一张卡。

### 8. 安全边界

- 明文只存在于两处：填的那一刻在设备内存里，以及节点的钥匙串里。中台、动作队列、视图缓存、日志里都没有。
- 日志只记「谁在何时换了哪个名字」，不记值、不记长度。
- 填密钥的输入框关掉自动填充与拼写检查；提交后立即清空；Web 上同样用 WebCrypto 封装后才离开页面。
- Web 的设备密钥较弱（`studio-standalone.md` §2.2），所以 `env.setSecret` 与 release 建议在桌面或手机上做，Web 上
  做时提示一句。
- `redactSecrets` 要认得这些值：节点在写入钥匙串时登记到本机的脱敏名单。

## 第二部分：设计稿整包上传

### 9. 收什么

- 来源：文件夹、zip、设计工具导出的包；桌面可拖入，手机与 Web 从文件里选。
- 类型白名单：图片（png / jpg / webp / svg）、pdf、标注与切图的 json、设计源文件（fig / sketch，只存不解析）。
- 上限（待定 5，下面是起步值）：单包 200 MB、单文件 25 MB、500 个文件。

`studio-standalone.md` §2.2 原来写「逐个确认后才上传」。一个包几十上百个文件，逐个点不现实，改成**一张清单**：

- 多少个文件、多大、几张图、几个标注文件。
- **跳过了哪些**，和原因：像密钥的（`isSecretPath` 的规则：`.env`、私钥、凭证文件）、不在白名单里的、超过单文件
  上限的。跳过的文件名显示出来，值不读。
- 客户看过清单点发出，才开始传。清单随时能再打开。

### 10. 怎么传

1. **压缩包在客户端解开**，得到逐个文件的清单（路径、大小、sha256、类型）。路径规范化，带 `..`、绝对路径、符号
   链接的一律跳过。中台和节点都不解压任何东西，躲开解压炸弹与路径穿越。
2. `asset.begin{projectRef, name, files[]}` → 中台回一个 `assetId` 和分片上传地址。
3. 分片上传，可暂停、可断点续传；sha256 对不上的分片重传。
4. `asset.commit{assetId}` → 状态 `ready`。
5. 需求可以**先发**：`request.create{..., assets: [assetId]}` 允许带还在 `uploading` 的包。分析等到包 `ready`，
   或等满 10 分钟后先按文字开始，包到了再触发一次 `request-reply`。

```ts
// 客户视图与主人视图都有
StudioAssetView = {
  id: REF, name: TITLE, rev: int,            // 同名再传一包是下一版，旧的保留
  status: 'uploading' | 'ready' | 'failed',
  count: int, bytes: int, skipped: int,
  thumbs: { path: TEXT, url?: string }[],    // 最多 4 张，签名链接 15 分钟
  at: int, by: WHO,
}
StudioRequestView.assets?: StudioAssetView[]
```

### 11. 存在哪

存中台的对象存储（Cloudflare R2），与 P2 的预览产物同一套签名链接（`studio-hub.md` §9）。原因：节点没有公网
地址，客户的设备传不到节点；节点离线时客户也要能传、能回看自己传过的东西。

- 保留期：项目存在期间；删项目或删账号时清除。
- 读取：传的人、同项目的客户、你；链接 15 分钟，逐文件签。
- 中台读得到这些文件。它们不是密钥，但可能是客户的商业机密，所以 `studio-terms.md` §2 要加一行，开通前发给客户。
- 另一种做法是封给节点、中台只存密文，代价是客户自己回看不了、缩略图也没有。见待定 4。

### 12. 节点怎么用

- `studio_request_get` 的结果里带 `assets[]`（清单，没有内容）。
- 新工具 `studio_asset_read(assetId, path)`：只给 `studio` 触发的分析 run 和规划回合，只读，返回图片或文本。
- **设计稿是材料，不是指令。** 图里、标注里的文字和客户的原话一样对待：用 `wrapCustomerText` 的同一套包裹说明，
  工具边界与客户回合相同，不因为图里写了什么而多做任何事。
- 节点把包下到项目之外的临时目录，按 sha256 缓存；**不自动写进工作树**。开发时要用到的切图，由开发的 run 显式
  复制进仓库，这一步出现在计划里。

### 13. 界面

- 提需求页：输入框里一张设计稿卡，有名称、文件数、大小、进度、四张缩略图、跳过的说明、「查看清单」。
- 对话里：一张设计稿卡（缩略图、名称、文件数、状态、「查看」）。
- 结果区「产物」：单独一组 **你提供的材料**，排在各次交付下面；多版时显示第几版。
- 手机：同一张卡，简化成一行；上传在后台继续，切走不中断。

## 14. 协议改动（都是加法）

- 主人动作：`env.put` / `env.setVar` / `env.delVar` / `env.setSecret` / `env.delSecret`。
- 客户动作白名单：`secret.provide`、`asset.begin`、`asset.commit`、`asset.remove`；`request.create` 与
  `request.say` 的载荷加可选 `assets`。
- 视图：主人视图加 `envs?: StudioEnvView[]`；需求单视图加 `assets?`；`gate.kind` 追加 `'release'`。
- 节点 → 设备：配对帧与信任同步里带节点公钥。
- 工具：`beluga_studio` 加 `studio_asset_read`。
- 旧客户端：不认识 `release` 的按未知 Gate 显示「在等工作室」；不认识 `assets` 的不显示卡，需求的文字照常。

## 15. 条款要改的（`studio-terms.md` §2）

| 数据 | 中台存不存 | 保留期 | 谁能读 |
|---|---|---|---|
| 环境的名字、变量、密钥的名字与用途 | 存（主人视图缓存） | 项目存在期间 | 运营方 |
| 密钥的值 | **不存明文**；动作队列里有密文 | 密文 7 天 | 只有那台节点解得开 |
| 你上传的设计稿与附件 | 存（对象存储） | 项目存在期间；删项目或账号时清除 | 你、同项目的客户、运营方 |

## 17. 待你决定

1. **分几个环境。** 本稿起步三个（测试、预发、正式），可删到两个。
2. **换上线节点时密钥怎么办。** (a) 重新填一遍，最简单；(b) 旧节点经「Your Computers」的端到端通道转给新节点，
   你在两台上各确认一次。本稿倾向 (a)。
3. **客户提供密钥时的换钥风险（§5）。** (a) 两边都显示节点公钥的指纹，你让客户核对；(b) 不做客户直填，客户线下
   给你，你来填；(c) 接受这个风险并写进条款。本稿倾向 (a)，重要的密钥用 (b)。
4. **设计稿包在中台存明文还是只存密文（§11）。** 本稿存明文，和预览一致。
5. **上传的上限**：单包 200 MB、单文件 25 MB、500 个文件。
6. **非正式环境的密钥能不能给 AI 用（§4）。** 本稿默认不给，逐个开。
