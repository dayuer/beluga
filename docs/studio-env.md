# 项目环境、密钥与设计稿上传（设计稿）

状态：**设计稿，未实施，未审计**。两件事写在一篇里，因为它们都要回答同一个问题：**客户交给 Studio 的东西
（密钥、设计稿）存在哪、谁读得到**。

- 第一部分：客户在 Studio 里维护每个项目的上线环境、变量与密钥，以及批准正式环境上线。
- 第二部分：提需求时把设计稿整包上传。

**前提（2026-11-18）**：客户是 Studio 唯一的使用者，自己做全部决定；Beluga 节点无人值守
（[`studio-standalone.md`](studio-standalone.md)）。同日较早的一版写的是「主人在 Studio 里维护环境、向客户要密钥」，
已作废。

先读：[`studio-standalone.md`](studio-standalone.md)（邀请、设备密钥与签名，§5）、[`studio-loop.md`](studio-loop.md)
（需求单、交付与预览，§5）、[`studio-forges.md`](studio-forges.md)（交付令牌）、[`studio-terms.md`](studio-terms.md)
（中台存什么）。界面见 [`studio-ui.md`](studio-ui.md) §3；画好的屏在 Claude Design 项目「Synon Studio 工作台」。

## 0. 结论摘要

- **环境与密钥的归属是节点，不是中台。** 定义和值都存在节点上；中台只转发，Studio 里只看得到名字、用途、更新时间、
  更新人。
- **客户填，客户设备封装，节点解开。** 客户在 Studio 里填密钥；值在客户的设备上用节点的公钥封好再发，中台与动作
  队列里只有密文。节点公钥来自邀请链接里的指纹（`studio-standalone.md` §5.2），中台换不了。所以
  `studio-terms.md`「中台永远不存密钥」可以原样保留。
- **密钥只写不读。** 界面上没有查看、没有复制；节点也不提供读回的接口，只提供「换」和「删」。
- **测试环境自动部署，正式环境要客户批准。** 每次检查通过后节点部署到测试环境，部署结果就是给客户看的预览；正式
  环境上线是一道 Gate（`release`），客户批准、设备签名。
- **设计稿包存在中台的对象存储里**，和 P2 的预览产物同一套（`studio-loop.md` §5.2）。它不是密钥，但会被中台读到，
  条款要补一行。压缩包在客户端解开，中台和节点都不解压。
- 这两部分都只做加法，`STUDIO_PROTO.major` 不动。

## 第一部分：环境与密钥

### 1. 模型

```ts
// 客户视图的「设置」里，只有客户自己的项目有
StudioEnvView = {
  id: string,                      // 'test' | 'staging' | 'prod' 起步，可改名、可删到只剩两个；test 必须有
  title: TITLE,                    // 测试 / 预发 / 正式
  protected: boolean,              // true：上线要过 release Gate，AI 的 run 拿不到这里的密钥
  target: { platform: Platform, appId?: string /* 中间打码 */, mode: TEXT },
  vars:    { name: NAME, value: TEXT, at: int, by: WHO }[],
  secrets: { name: NAME, purpose: TEXT, at: int, by: WHO, staleDays?: int }[],   // 没有 value
  lastRelease?: { version: TEXT, at: int, by: WHO },
}
WHO = { name: TITLE, via: 'studio' | 'setup' }   // 客户在 Studio 里，或搭环境的人在节点 CLI 里预置
```

- `at`（时间）与 `by`（人）是两个字段，界面上也是**两列**，不拼成一句。
- `NAME` 只收 `[A-Z][A-Z0-9_]{0,63}`；`value` 上限 4 KB，密钥明文上限 16 KB（证书、私钥文件够用）。
- 变量是非机密的（接口地址、开关）：值进视图，过 `redactSecrets`，长得像密钥的拒收并提示「这个应该放进密钥」。
- 落盘：节点上 `studio-env.json`（0600），密钥的值进系统钥匙串，没有钥匙串的无窗口节点用 0600 文件。按项目隔离，
  随项目删除而删除。不进 store、不进视图、不进日志。

### 2. 密钥怎么从客户的设备到节点

1. **节点有自己的一对密钥**（X25519），第一次连接 Studio 时生成，私钥不离开那台机器。
2. **客户的设备怎么认得节点的公钥**：邀请链接 `#` 后面带着发邀请那台节点的公钥指纹，设备登记时核对过
   （`studio-standalone.md` §5.2）。项目池里的其他节点，公钥由这台节点签名后经中台转给设备；设备只认这台节点签过的。
3. **封装**：设备把值**分别封给项目池里的每一台节点**（sealed box），发
   `env.setSecret{projectRef, envId, name, purpose, sealed: {nodeKey → box}[], at}`，整帧用设备密钥签名。
4. **中台**只看到密文，照常进动作队列（节点离线时最多留 7 天）。队列里是密文，不改变「不存密钥」这句话。
5. **节点**验签、查设备在信任名单里、找到封给自己的那一份，解开，写入钥匙串，回执 `done`；视图里这一行的 `at` 与
   `by` 更新。
6. **池里新加了节点**：它没有已有的密钥。客户下次打开 Studio 时，设备看到「有 1 台执行机器还没有这些密钥」，点一下
   重新封一遍（设备上没有明文，所以要客户重新填）。见待定 2。

### 3. 动作（都是客户的，都要签名）

| 动作 | 载荷 | 结果 |
|---|---|---|
| `env.put` | `{projectRef, envId, title?, target?, protected?}` | 建或改一个环境 |
| `env.setVar` | `{projectRef, envId, name, value}` | 写变量 |
| `env.delVar` | `{projectRef, envId, name}` | 删变量 |
| `env.setSecret` | 见 §2 | 写或换密钥 |
| `env.delSecret` | `{projectRef, envId, name}` | 删密钥 |
| `release.approve` | `{projectRef, envId, version}` | 批准上线（§6） |

没有 `env.getSecret`，协议里不留这个名字。搭环境的人可以在节点上用 `beluga studio env set …` 预置，`by.via` 记
`setup`；之后客户在 Studio 里可以照常更换。

### 4. 谁用得到这些值

| 用的地方 | 变量 | 非 `protected` 环境的密钥 | `protected` 环境的密钥 |
|---|---|---|---|
| AI 的开发与检查 run | 可以（进环境变量） | 逐个开「给 AI 用」才可以，默认关 | **永远拿不到** |
| 客户回合（分析、规划） | 不给 | 不给 | 不给 |
| 上线步骤（节点的流水线，不是 agent 的工具） | 可以 | 可以 | 可以，且只在 release Gate 通过后 |

上线步骤本身（上传小程序代码、发 TestFlight、部署 Web）是节点上的脚本，每个平台的适配另写；本文只定配置从哪来、
谁批准。脚本的输出过 `redactSecrets` 后才进视图，并且把这次注入过的值逐个加进脱敏名单。

### 5. 测试环境：自动部署，就是预览

- 每个项目必须有一个测试环境，`protected: false`。
- 每一轮代码合并后，节点自动部署到测试环境；部署出的地址或体验版就是交付卡上的预览（`studio-loop.md` §5.2）。
- 测试环境部署失败：重试三次，仍不行按「需要人」处理；如果是因为测试环境的密钥缺失或过期，客户看到红点
  「测试环境的 XXX 需要更换」，因为只有客户能修。

### 6. 上线 Gate

```ts
StudioGate.kind 追加 'release'
```

- 只有 `protected` 环境要过。客户**通过**交付之后才升起；一个环境同一时间只有一张。
- 上线卡出现在对话里与待办里：环境、要上的版本（交付标签 `delivery/<n>`）、上次上线的版本与时间。动作 **上线**
  （主，签名，二次确认）与 **先不上…**（写原因）。
- 上线中按钮自己显示进度；成功后卡上写「已上线 1.8.3」；失败按 §5 同样的规则区分「等待」与「要你处理」。
- 客户可以在设置里把正式环境关掉（只交付到测试环境），那就没有上线卡。

### 7. 界面

位置：**设置 › 环境与密钥**（`studio-ui.md` §3）。上面一排分段选环境；下面三块：上线到哪里、变量、密钥。

- 表格的列：名称、值或用途、**更新时间**、**更新人**、动作。时间和人各占一列。
- 密钥的值永远画成圆点。动作只有「更换」，删除在 ••• 里且二次确认。超过 90 天没换的密钥在用途旁标一句，节点本地算，
  不发提醒。
- 保存按钮旁写「由这台设备确认」。这一页没有「等你做」的事，所以不放实底按钮；实底只在上线卡上。
- 手机：只读名称、用途、更新时间、更新人；填和换只在桌面与 Web 做。上线卡在手机上可以批。

### 8. 安全边界

- 明文只存在于两处：填的那一刻在客户设备的内存里，以及节点的钥匙串里。中台、动作队列、视图缓存、日志里都没有。
- 日志只记「谁在何时换了哪个名字」，不记值、不记长度。
- 填密钥的输入框关掉自动填充与拼写检查；提交后立即清空；Web 上同样用 WebCrypto 封装后才离开页面。
- Web 的设备密钥较弱（`studio-standalone.md` §2.2），所以 `env.setSecret` 与上线建议在桌面或手机上做，Web 上做时
  提示一句。
- `redactSecrets` 要认得这些值：节点在写入钥匙串时登记到本机的脱敏名单。
- 对话里的文字永远改不了环境与密钥：agent 读不到设置，也没有写设置的工具。

## 第二部分：设计稿整包上传

### 9. 收什么

- 来源：文件夹、zip、设计工具导出的包；桌面可拖入，手机与 Web 从文件里选。
- 类型白名单：图片（png / jpg / webp / svg）、pdf、标注与切图的 json、设计源文件（fig / sketch，只存不解析）。
- 上限（待定 5，下面是起步值）：单包 200 MB、单文件 25 MB、500 个文件。

一个包几十上百个文件，逐个点确认不现实，改成**一张清单**：

- 多少个文件、多大、几张图、几个标注文件。
- **跳过了哪些**，和原因：像密钥的（`isSecretPath` 的规则：`.env`、私钥、凭证文件）、不在白名单里的、超过单文件
  上限的。跳过的文件名显示出来，值不读。跳过不是出错，用灰字说明，不拦住发送。
- 客户看过清单点发出，才开始传。清单随时能再打开。

### 10. 怎么传

1. **压缩包在客户端解开**，得到逐个文件的清单（路径、大小、sha256、类型）。路径规范化，带 `..`、绝对路径、符号
   链接的一律跳过。中台和节点都不解压任何东西，躲开解压炸弹与路径穿越。
2. `asset.begin{projectRef, name, files[]}` → 中台回一个 `assetId` 和分片上传地址。
3. 分片上传，可暂停、可断点续传；sha256 对不上的分片重传。
4. `asset.commit{assetId}` → 状态 `ready`。
5. 需求可以**先发**：`request.create{..., assets: [assetId]}` 允许带还在 `uploading` 的包。分析等到包 `ready`，
   或等满 10 分钟后先按文字开始，包到了再触发一次 `request-reply`。

```ts
StudioAssetView = {
  id: REF, name: TITLE, rev: int,            // 同名再传一包是下一版，旧的保留
  status: 'uploading' | 'ready' | 'failed',
  count: int, bytes: int, skipped: int,
  thumbs: { path: TEXT, url?: string }[],    // 最多 4 张，签名链接 15 分钟
  at: int, by: WHO,
}
StudioRequestView.assets?: StudioAssetView[]
```

### 11. 存在哪

存中台的对象存储（Cloudflare R2），与 P2 的预览产物同一套签名链接（`studio-hub.md` §9）。原因：节点没有公网
地址，客户的设备传不到节点；节点离线时客户也要能传、能回看自己传过的东西。

- 保留期：项目存在期间；删项目或删账号时清除。
- 读取：传的人、同项目的其他客户；链接 15 分钟，逐文件签。
- 中台读得到这些文件。它们不是密钥，但可能是客户的商业机密，所以 `studio-terms.md` §2 要加一行，开通前发给客户。
- 另一种做法是封给节点、中台只存密文，代价是客户自己回看不了、缩略图也没有。见待定 4。

### 12. 节点怎么用

- `studio_request_get` 的结果里带 `assets[]`（清单，没有内容）。
- 新工具 `studio_asset_read(assetId, path)`：只给 `studio` 触发的分析 run 和规划回合，只读，返回图片或文本。
- **设计稿是材料，不是指令。** 图里、标注里的文字和客户的原话一样对待：用 `wrapCustomerText` 的同一套包裹说明，
  工具边界与客户回合相同，不因为图里写了什么而多做任何事。
- 节点把包下到项目之外的临时目录，按 sha256 缓存；**不自动写进工作树**。开发时要用到的切图，由开发的 run 显式
  复制进仓库，这一步出现在计划里。

### 13. 界面

- 提需求页：输入框里一张设计稿卡，有名称、文件数、大小、进度、四张缩略图、跳过的说明、「查看清单」。
- 对话里：一张设计稿卡（缩略图、名称、文件数、状态、「查看」）。
- 结果区「产物」：单独一组 **你提供的材料**，排在各次交付下面；多版时显示第几版。
- 手机：同一张卡，简化成一行；上传在后台继续，切走不中断。

## 14. 协议改动（都是加法）

- 客户动作（签名）：`env.put` / `env.setVar` / `env.delVar` / `env.setSecret` / `env.delSecret` / `release.approve`。
- 客户动作（白名单，不签名）：`asset.begin`、`asset.commit`、`asset.remove`；`request.create` 与 `request.say` 的
  载荷加可选 `assets`。
- 视图：客户视图的设置部分加 `envs?: StudioEnvView[]`；需求单视图加 `assets?`；`gate.kind` 追加 `'release'`。
- 节点 → 设备：池里其他节点的公钥，由发邀请的节点签名。
- 工具：`beluga_studio` 加 `studio_asset_read`。
- 旧客户端：不认识 `release` 的显示「快好了」，没有按钮；不认识 `assets` 的不显示卡，需求的文字照常。

## 15. 条款要改的（`studio-terms.md` §2）

| 数据 | 中台存不存 | 保留期 | 谁能读 |
|---|---|---|---|
| 环境的名字、变量、密钥的名字与用途 | 存（视图缓存） | 项目存在期间 | 运营方 |
| 密钥的值 | **不存明文**；动作队列里有密文 | 密文 7 天 | 只有节点解得开 |
| 你上传的设计稿与附件 | 存（对象存储） | 项目存在期间；删项目或账号时清除 | 你、同项目的其他客户、运营方 |

## 17. 待你决定

1. **分几个环境。** 本稿起步三个（测试、预发、正式），测试必须有，其余可删。
2. **池里加了新节点时，密钥怎么到它那里（§2.6）。** (a) 客户重新填一遍，最简单；(b) 已有密钥的节点经
   「Your Computers」的端到端通道转给新节点，客户在 Studio 里确认一次。本稿倾向 (b)：无人值守的集群里节点会换，
   每次都让客户重填不现实。
3. **搭环境的人能不能预置密钥（§3）。** 本稿能，方便首次上线；客户之后可以换掉。
4. **设计稿包在中台存明文还是只存密文（§11）。** 本稿存明文，和预览一致。
5. **上传的上限**：单包 200 MB、单文件 25 MB、500 个文件。
6. **非正式环境的密钥能不能给 AI 用（§4）。** 本稿默认不给，逐个开。
